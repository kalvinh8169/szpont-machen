# Releasing szpont

## One-time setup (before the first release)

1. Create the GitHub repo and push: `gh repo create tjzel/szpont-machen --public --source . --push`
2. Create the Homebrew tap repo: `gh repo create tjzel/homebrew-tap --public`
3. Add repo secrets (Settings → Secrets → Actions):
   - `HOMEBREW_TAP_TOKEN` — a fine-grained PAT with write access to `tjzel/homebrew-tap`
   - `CARGO_REGISTRY_TOKEN` — from https://crates.io/settings/tokens (scope: publish-update)

## Every release

1. Bump `version` in `szpont/Cargo.toml`, commit.
2. Tag and push: `git tag v<X.Y.Z> && git push && git push --tags`

The `release.yml` workflow (generated by cargo-dist; regenerate with `dist generate` after
config changes in `dist-workspace.toml`) then:

- builds macOS (arm64, x86_64) and Linux (arm64, x86_64) binaries
- publishes a GitHub Release with tarballs, checksums and a shell installer
- updates the Homebrew formula in `tjzel/homebrew-tap`
- publishes the crate to crates.io (`publish-crates.yml`)

## Install channels this produces

```sh
curl -fsSL https://github.com/tjzel/szpont-machen/releases/latest/download/szpont-installer.sh | sh
brew install tjzel/tap/szpont
cargo install szpont
cargo install --git https://github.com/tjzel/szpont-machen szpont
```

Shell-installer users also get a `szpont-update` companion binary (axoupdater) that
self-updates to the newest GitHub release. Homebrew users update via `brew upgrade szpont`,
cargo users via `cargo install szpont`.

Validate locally before tagging: `dist plan` and `cargo publish -p szpont --dry-run`.
